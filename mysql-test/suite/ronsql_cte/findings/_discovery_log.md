Legend: ERROR = clean RonSQL permanent error; HANG = never returns;
WRONG = wrong values vs MySQL; PLAN = values OK but EXPLAIN plan differs.

## Confirmed WORKING so far (green)

- `agg-04`: scalar main agg (MIN/MAX/SUM-int) over a CTE keyed by o_custkey (300) joined to the small `customer` parent.
- smoke: P-GB (`GROUP BY c_mktsegment`) over the same CTE shape, SUM(int)/COUNT(*).
- `agg-05` cleanly ERRORS ("Not an aggregate query") — projection emulated via `GROUP BY <all cte cols>` over a CTE_LOOKUP is rejected, not crashed.

## Emerging picture

The realistic broad shapes are hitting a clean-error class (D1 SUM-over-DECIMAL,
non-aggregate-over-unsupported-CTE) AND several **hang/crash** classes (D2–D6).
The genuinely-stable envelope is narrow: aggregating main SELECTs over a CTE
keyed by a moderate-cardinality key joined to a SMALL parent. High-cardinality
keys / large root scans / projection-only-over-lookup / col-vs-col / 3-table
real-cte-real chains are unstable on this build.
