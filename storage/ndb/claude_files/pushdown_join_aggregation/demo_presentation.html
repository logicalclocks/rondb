Demo 1: Inner Join Chain

nation ──→ supplier ──→ lineitem │ │ │ GROUP BY join key SUM + COUNT (n_name) (nationkey) (extendedprice)

Three tables chained together
Millions of lineitems reduced to 25 rows (one per nation)

Demo 2: LEFT JOIN

customer ──LEFT JOIN──→ orders │ │ GROUP BY SUM + COUNT (mktsegment) (totalprice) Customer with no orders? Still counted ── NULL propagated on data node

Outer join semantics handled entirely inside the data node

Demo 3: Star Schema

nation ╱ ╲ SUM(supplier.balance) COUNT(customer) Leaf 1 Leaf 2 independent independent

Two correlated subqueries on different tables
Each becomes its own leaf scan — no merge needed

Demo 4: Subquery Merge

nation ╱ | ╲ SUM(s.bal) MAX(s.bal) COUNT(cust) ╲ ╱ │ MERGED ── 1 scan separate leaf

Two aggregates on same table → merged into a single leaf scan
Third subquery on a different table stays separate

Demo 5: CASE + Filters

orders ──→ lineitem │ │ WHERE year GROUP BY shipmode │ CASE priority URGENT → count in bucket 1 OTHER → count in bucket 2

Cross-table WHERE + CASE expressions
All evaluated on the data node, only 7 ship modes returned
